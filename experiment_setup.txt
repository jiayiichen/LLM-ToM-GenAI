1. RESEARCH QUESTIONS
================================================================================

RQ1: Are LLMs truly incapable of ToM tasks, or are current benchmarks
     underestimating their capabilities?

RQ2: When LLMs fail on ToM tasks, what systematic failure modes emerge?

RQ3: Can targeted data synthesis based on failure patterns improve model
     performance on ToM tasks?

4. DATASET
================================================================================

Benchmark: ToMBench (Chen et al., 2024)
Source: https://github.com/zhchen18/ToMBench

Dataset Statistics:
- Total samples: 2,860 (train: 2,003 + test: 857)
- Task types: 8 core ToM tasks
- Cognitive abilities: 31 different abilities tested
- Format: Multiple choice (A, B, C, D)

Task Types in ToMBench:
1. False Belief Task
2. Faux-pas Recognition Test
3. Strange Story Task
4. Hinting Task Test
5. Scalar Implicature Test
6. Persuasion Story Task
7. Ambiguous Story Task
8. Unexpected Outcome Test
+ Additional specialized tasks (Emotion, Knowledge, Prediction, etc.)

Data Files:
- train.csv: 2,003 training samples
- test.csv: 857 test samples
- tombench_csvs/: Individual task CSVs

6. EXPERIMENT PHASES
================================================================================

PHASE 1: BENCHMARK EVALUATION
-----------------------------
Objective: Establish baseline performance across all models

Procedure:
1. Run inference on test.csv (857 samples) for each model
2. Extract answers in [[A]]/[[B]]/[[C]]/[[D]] format
3. Calculate accuracy

Prompt Template (CoT version - eval/prompt.txt):
- Instructs model to reason step-by-step
- Requires final answer in [[X]] format
- Forces selection even with insufficient information

Prompt Template (No-CoT version - finetune training):
- Direct answer output only
- Format: "Output [[A]], [[B]], [[C]], or [[D]], and nothing else"

Scripts:
- eval/run_evaluation.py: OpenRouter API evaluation
- eval/run_evaluation_vllm.py: VLLM evaluation
- inference_submission/inference.py: Vertex AI evaluation

Output:
- results/gpt_test_results.csv
- results/Qwen2.5-7B-Instruct/Qwen2.5-7B-Instruct_train_results.csv


PHASE 2: FAILURE ANALYSIS
-------------------------
Objective: Identify and categorize why models fail on specific questions

Procedure:
1. Extract failure cases (incorrect predictions)
2. Use GPT5.1 to summarize failure reasons via CoT analysis
3. Generate structured failure summaries

Failure Summarization Prompts:
- hierarchical_cluster/failure_summarizer_layer1.txt
- hierarchical_cluster/failure_summarizer_layer2.txt

Scripts:
- hierarchical_cluster/failure_summarizer.py
- hierarchical_cluster/extract_failures.py

Output:
- failures/qwen2_5_7b_instruct_noCoT_*_failures.csv
- hierarchical_cluster/qwen2_5_7b_instruct_noCoT_failure_analysis_645cases.csv


PHASE 3: HIERARCHICAL CLUSTERING
--------------------------------
Objective: Group failures into interpretable categories

Method: AI-assisted hierarchical summarization (3 layers)

Layer 1: Individual Failure Summaries
- Each failure case gets a brief summary of why model failed
- 645 individual summaries

Layer 2: Cluster Formation
- Group similar failures using embedding similarity
- Form 80 mid-level clusters
- Generate cluster summaries

Layer 3: High-Level Categories
- Further aggregate into 10 interpretable categories
- Calculate objectivity scores (1-10) for each cluster
- Select clusters with objectivity > 5 for data synthesis
- Selected clusters: 4, 5, 9 (table numbering)

Scripts:
- hierarchical_cluster/summarizer_layer1.ipynb
- hierarchical_cluster/summarizer_layer2.ipynb
- hierarchical_cluster/summarizer_layer3.ipynb
- hierarchical_cluster/clustering/round1_clustering.ipynb
- hierarchical_cluster/clustering/round2_clustering.ipynb
- hierarchical_cluster/connecting_layer.ipynb

Output:
- hierarchical_cluster/cluster_analysis_layer2/
- hierarchical_cluster/cluster_analysis_layer3/
- hierarchical_cluster/connecting_layers/


PHASE 4: DATA SYNTHESIS
-----------------------
Objective: Generate targeted training data for identified failure patterns

Method: GPT-5.1 prompted synthesis with cluster-specific examples

Procedure:
1. For each selected cluster:
   a. Extract cluster summary (failure pattern description)
   b. Sample 2 representative failure examples
   c. Prompt GPT-5.1 to generate 10 similar questions
2. Run multiple batches per cluster (multithreaded)
3. Validate JSON format and question structure

Synthesis Configuration:
- Model: openai/gpt-5.1 (via OpenRouter)
- Temperature: 2.0 (high diversity)
- Batch size: 10 questions per API call

Data Generated:
- Cluster 4: 400 questions
- Cluster 5: 281 questions
- Cluster 9: 110 questions
- Total synthesized: 791 questions

Scripts:
- data_synthesis/data_synthesize.ipynb (main notebook)
- data_synthesis/data_synthesize_prompt.txt (prompt template)

Output:
- results/synthesized_data/data/*.csv


PHASE 5: FINETUNING
-------------------
Objective: Improve Qwen2.5-7B on ToM tasks using synthesized data

Method: Full parameter finetuning (not LoRA/PEFT)

Training Configurations:

A. Without Synthesized Data (baseline):
   - Train: 1,802 samples (90% of train.csv)
   - Val: 201 samples (10% of train.csv)
   - Output: finetune/finetune_without_syn/

B. With Synthesized Data:
   - Train: 2,514 samples (original + synthesized)
   - Val: 280 samples
   - Output: finetune/finetune_with_moresyn/

Hyperparameters:
- Base model: Qwen/Qwen2.5-7B-Instruct
- Epochs: 1
- Batch size: 2
- Gradient accumulation: 8
- Effective batch size: 16
- Learning rate: 2e-5
- Scheduler: Cosine with 3% warmup
- Precision: BF16
- Max sequence length: 2048
- Gradient checkpointing: Enabled

Hardware:
- GPU: 1x NVIDIA H100 (94GB VRAM)
- Training time: ~15-20 minutes per run

Label Masking:
- Loss computed only on assistant response tokens
- User prompt tokens masked with -100

Scripts:
- finetune/finetune_qwen.py
- finetune/prepare_finetuning_data.ipynb

Output:
- Model weights (~14GB safetensors)
- Training logs (TensorBoard)


PHASE 6: EVALUATION
-------------------
Objective: Compare finetuned models against baselines

Test Set: test.csv (857 samples)

Models Compared:
1. GPT (baseline SOTA)
2. Qwen2.5-7B finetuned WITHOUT synthesized data
3. Qwen2.5-7B finetuned WITH synthesized data

Metrics:
- Overall accuracy
- Per-task accuracy
- Accuracy delta (improvement from synthesis)

Scripts:
- eval/run_evaluation.py
- eval/run_evaluation_vllm.py (for local models)

9. TROUBLESHOOTING GUIDE
================================================================================

ISSUE 1: "OPENROUTER_API_KEY not found"
---------------------------------------
Symptom:
  OpenAIError: The api_key client option must be set...

Solution:
  # Set environment variable
  export OPENROUTER_API_KEY="sk-or-v1-your-key"

  # Or in Python before imports:
  import os
  os.environ["OPENROUTER_API_KEY"] = "your-key"

  # For Jupyter notebooks, add to first cell:
  import os
  with open(os.path.expanduser('~/.bashrc'), 'r') as f:
      for line in f:
          if 'OPENROUTER_API_KEY' in line:
              key = line.split('=')[1].strip()
              os.environ["OPENROUTER_API_KEY"] = key


ISSUE 2: "gcloud: command not found"
------------------------------------
Symptom:
  RuntimeError: gcloud CLI not found

Solution:
  # Install Google Cloud SDK
  # Linux/Mac:
  curl https://sdk.cloud.google.com | bash
  exec -l $SHELL
  gcloud init

  # Or download from:
  https://cloud.google.com/sdk/docs/install


ISSUE 3: CUDA Out of Memory during Finetuning
---------------------------------------------
Symptom:
  torch.cuda.OutOfMemoryError: CUDA out of memory

Solutions:
  # Option 1: Reduce batch size
  # In finetune_qwen.py, change:
  per_device_train_batch_size: int = field(default=1)  # was 2

  # Option 2: Enable gradient checkpointing (already enabled by default)
  gradient_checkpointing: bool = field(default=True)

  # Option 3: Use DeepSpeed (for multi-GPU)
  # Uncomment in finetune_qwen.py:
  deepspeed: Optional[str] = field(default="deepspeed_config.json")


ISSUE 4: JSON Decode Error in Data Synthesis
--------------------------------------------
Symptom:
  json.JSONDecodeError: Expecting property name

Solution:
  # The API sometimes returns malformed JSON
  # The code has retry logic (max_retries=3)

  # If persistent, try:
  # 1. Lower temperature (e.g., 1.5 instead of 2.0)
  # 2. Increase max_tokens
  # 3. Check API rate limits


ISSUE 5: Import Errors
----------------------
Symptom:
  ModuleNotFoundError: No module named 'xxx'

Solution:
  # Install missing dependencies
  pip install -r requirements.txt

  # For specific packages:
  pip install transformers datasets accelerate


ISSUE 6: Slow Inference
-----------------------
Symptom:
  API calls taking too long, timeouts

Solutions:
  # 1. Check rate limits (default: 6 sec delay)
  REQUEST_DELAY_SECONDS = 6  # in inference.py

  # 2. Use multithreading for synthesis
  MAX_WORKERS = 4  # in data_synthesize.ipynb

  # 3. For local models, use vLLM:
  python eval/run_evaluation_vllm.py


ISSUE 7: Test Failures
----------------------
Symptom:
  pytest unit_tests fail

Solution:
  # Check Python version (need 3.10+)
  python --version

  # Reinstall test dependencies
  pip install pytest pandas

  # Run with verbose output
  python -m pytest unit_tests/ -v --tb=long


ISSUE 8: Permission Denied on Model Files
-----------------------------------------
Symptom:
  PermissionError when loading finetuned model

Solution:
  # Fix permissions
  chmod -R 755 finetune/finetune_without_syn/

  # Or run as appropriate user
  sudo chown -R $USER:$USER finetune/


ISSUE 9: Tokenizer Warnings
---------------------------
Symptom:
  "Token indices sequence length is longer than the specified maximum"

Solution:
  # This is usually safe to ignore
  # Or increase max_seq_length in finetune_qwen.py:
  max_seq_length: int = field(default=4096)  # was 2048


ISSUE 10: Results Don't Match Expected
--------------------------------------
Symptom:
  Accuracy numbers differ from paper/documentation

Checklist:
  1. Verify using correct test.csv (857 samples)
  2. Check prompt template matches (CoT vs no-CoT)
  3. Ensure temperature=0 for deterministic results
  4. Verify answer extraction regex: r'\[\[([A-D])\]\]'
